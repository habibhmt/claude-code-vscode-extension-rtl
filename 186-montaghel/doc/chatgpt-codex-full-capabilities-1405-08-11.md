# فهرست امکانات ChatGPT و Codex و دسترسی‌های همین مک

بررسی ۱۱ آبان ۱۴۰۵، نوبت بعدازظهر. این فهرست از سه بخش رسمیِ [امکانات](https://learn.chatgpt.com/docs/features)، [تنظیمات](https://learn.chatgpt.com/docs/configuration) و [ابزارهای توسعه](https://learn.chatgpt.com/docs/developers) ساخته شده، نه فقط جدول قدیمی کلود. مسیرهای تکراری و صفحه‌های توضیح یک قابلیت در یک ردیف جمع شده‌اند. فهرست منابع در فایل کنار این گزارش است.

**معنی وضعیت‌ها:** «استفاده شد» فقط برای همان کار ذکرشده؛ «ابزار هست» یعنی در این چت در دسترس است ولی اجرای آن امتحان نشده؛ «راهنما» یعنی در مستند رسمی آمده و فعال‌بودنش برای حساب تو تأیید نشده. فهرست امکانات با آزمایش همهٔ آن‌ها فرق دارد.

| ساخت ویدئو / Sora | [راهنمای ویدئو](https://learn.chatgpt.com/learn/videogen) وجود دارد؛ ابزار ساخت مستقیم ویدئو در این چت پیدا نشد و شامل‌بودن آن در اشتراک تو تأیید نشده. |
| اشتراک‌گذاری دوربین یا صفحه در Voiceِ Chat | در همان راهنمای تنظیمات سازمانی آمده؛ مسیر و دسترسی حساب تو آزمایش نشده. با Appshot و Screen context یکی حساب نشود. |

## پلاگین و هوک؛ دقیقاً چه شد؟

| سؤال تو | نتیجهٔ واقعی |
|---|---|
| پلاگین در Codex هست؟ | بله؛ تنظیمات و ابزارهای محلی آن بررسی شد. |
| هوک در Codex هست؟ | بله؛ مستند رسمی و پاسخ واقعی `hooks/list` آن را نشان داد. |
| Hookify را باید نصب یا روشن کنیم؟ | از قبل نصب، enabled و trusted بود؛ چهار رویداد آن در پاسخ Codex بود. دوباره نصب یا روشن‌کردن لازم نبود. |
| برای این پروژه قانونی دارد؟ | پیش از آزمایش، فایل `hookify.*.local.md` در `.claude` این پروژه نبود. |
| خودِ برنامه قانون را می‌فهمد؟ | در پوشهٔ جدا، نمونهٔ معمولی مجاز بود و نمونهٔ دارای علامت آزمایش، پاسخ deny گرفت؛ با خاموش‌کردن همان قانون، deny برداشته شد. |
| در همین چت هم جلوی فرمان را گرفت؟ | نه. قانون موقتِ مخصوص یک علامت بی‌خطر گذاشتم؛ فرمان از مسیر `functions.exec → exec_command` اجرا شد. قانون آزمایشی بلافاصله حذف شد. |
| علت معلوم شد؟ | نه. پاسخِ تنظیماتِ یک App Server تازه، وضعیتِ بارگذاریِ همین چت را اثبات نمی‌کند. تلاش خواندن هوک‌های چت از سرور مشترک جواب نداد. تفاوت نسخهٔ CLI و نسخهٔ همراه اپ دیده شد، ولی علتِ خطا اثبات نشد. |
| الآن می‌شود به آن تکیه کرد؟ | برای جلوگیری در مسیر ابزار همین چت، هنوز نه. نصب و trusted بودن کافی نبود. هیچ محافظتی را خاموش نکردم و قوانین خودت دست نخورد. |

محدودیت دیگرِ آزمون: ورودی‌های Write و apply_patch و Bash یک شکل نیستند؛ قانونِ نوشته‌شده برای یکی را بدون آزمون برای دیگری معتبر حساب نکن. [راهنمای ورودی و پوشش هوک‌ها](https://learn.chatgpt.com/docs/hooks#tool-coverage)

منابع این مقایسه: [راهنمای رسمی Claude](https://support.claude.com/en/articles/14128542-let-claude-use-your-computer-in-cowork)، [راهنمای رسمی ChatGPT](https://learn.chatgpt.com/docs/computer-use)، [مرورگر ChatGPT](https://learn.chatgpt.com/docs/chrome-extension)، و بخش Tiered apps در اسکیل Computer Use نصب‌شدهٔ خود Claude روی این مک. رفتار واقعیِ تک‌تک برنامه‌های Claude در این نوبت آزمایش نشده.

| «همه دسترسی‌ها باز است؟» | آنچه الآن چک شد |
|---|---|
| اجازهٔ اصلی مک برای Claude | در پایگاه اجازه‌های مک، ثبتِ دسترسیِ دیدن صفحه، کنترل رابط و دسترسی کامل فایل دیده شد. این ثبت را اجرای موفق فعلی حساب نکن. |
| اجازهٔ اصلی مک برای ChatGPT/Codex | همان سه نوع دسترسی برای اپ/سرویس مربوط ثبت شده‌اند. |
| ابزار کامپیوترِ همین چت | ابتدا تنظیمات مک را خواند؛ بعد دو بار بی‌پاسخ ماند و در تلاش بعدی `Sky Computer Use native pipe startup failed` داد. |
| ابزار مرورگر همین چت | فهرست مرورگرها خالی و پاسخ `The browser access host is unavailable` بود. |
| اجازهٔ حساب برای افزونه‌ها | ابزار مدیریت اجازه‌ها مقدار پیش‌فرض `Allow low-risk actions` داد؛ یعنی اجازهٔ خودکار کارهای کم‌خطر، نه همهٔ کارها. Gmail از همین پیش‌فرض پیروی می‌کند. |
| اجازهٔ برنامه‌به‌برنامه داخل Claude | در این نوبت نتوانستم صفحهٔ داخلی آن را بخوانم؛ فهرستِ همهٔ برنامه‌های مجاز/ممنوع تأیید نشده. |
| نتیجه | بازبودن اجازه‌های اصلی مک به معنی وصل‌بودن ابزار، مجازبودن هر برنامه یا مجازبودن هر عمل نیست. |

نکتهٔ تشخیص: ابزار مدیریت پلاگینِ حساب برای نام «Computer Use» پاسخ `not_installed` داد، در حالی که تنظیم محلی و ابزار فعال همین چت خلافِ تعمیم آن را نشان می‌دادند. این پاسخ را فقط وضعیت همان مسیرِ مدیریت پلاگین حساب حساب کردم؛ نتیجه نگرفتم که ابزار محلی نصب نیست.

اگر عبارتِ گفتاری تو «Locked use» بود: یعنی استفاده هنگام قفل‌بودن مک؛ نه بازشدن همهٔ اجازه‌ها. اگر «Blocked» بود: یعنی برنامه یا عمل ممنوع شده. این دو یکی نیستند. فعال‌بودن Locked use روی مک تو تأیید نشده.
