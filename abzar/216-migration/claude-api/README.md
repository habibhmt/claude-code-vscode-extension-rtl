# Claude Code با DeepSeek از OpenRouter

حبیب گفت فعلاً فقط Claude Code آماده شود و کلید را بعداً فراهم می‌کند. این بسته مسیر جداگانهٔ آزمایشی است؛ تنظیم سراسری، ورود حساب و چت‌های موجود تغییر نکرده‌اند. نسخهٔ فعلی CLI با `claude --version` بررسی می‌شود.

| آماده شده | محدوده |
|---|---|
| فایل تنظیم بدون کلید | مدل `deepseek/deepseek-v4.1-flash-1017` و نشانی Anthropic-compatible (قالب ارتباطی Claude) در OpenRouter |
| راه‌انداز جدا | تاریخچه و تنظیم اجرای آزمایشی در `.runtime/claude-deepseek`؛ فایل‌های اصلی در `~/.claude` دست‌نخورده |
| آزمون اولیه | خواندن فایل ساختگی و گزارش جمع ۹۱ به فارسی؛ فقط ابزار Read، بدون دستیار فرزند |
| شروع تعاملی | تأیید دستی اقدامات؛ از پوشهٔ نمونه شروع می‌شود؛ این جداسازی تنظیم است، نه محفظهٔ امنیتی سیستم‌عامل |
| بودجه | کلید اختصاصی با سقف کل غیرقابل‌تمدید حداکثر ۴ دلار؛ ۱ دلار از سقف ۵دلاری حبیب برای کارمزد کنار گذاشته شده |

## اکنون، بدون کلید

از ریشهٔ همین پروژه:

```sh
python3 scripts/claude_deepseek.py check
python3 scripts/test_claude_deepseek.py
```

این فرمان‌ها به مدل درخواست نمی‌دهند. خروجی `prepared_not_connected` یعنی آماده‌سازی محلی، نه اتصال موفق.

## وقتی کلید آماده شد

کلید اختصاصیِ این آزمایش در حساب OpenRouter باید سقف حداکثر ۴ دلار، بدون بازنشانی روزانه/ماهانه و با احتساب BYOK (مصرف کلیدِ ارائه‌دهندهٔ دیگر) داشته باشد. سقف کلید قبل از اجرای Claude از مسیر ثابت `https://openrouter.ai/api/v1/key` خوانده می‌شود؛ کلید نامحدود یا پاسخ مبهم رد می‌شود. این برنامه کلید نمی‌سازد، شارژ نمی‌کند و تنظیم حساب را عوض نمی‌کند. کارمزد واقعیِ هر شارژ باید پیش از خرید با ماندهٔ سقف کل تطبیق داده شود؛ عدد ذخیرهٔ ۱ دلار، تضمین کارمزد همهٔ روش‌های پرداخت نیست.

```sh
python3 scripts/claude_deepseek.py smoke
```

در ترمینال، کلید بدون نمایش پرسیده می‌شود و روی دیسک ذخیره نمی‌شود. می‌توان از متغیر محیطی `OPENROUTER_API_KEY` نیز استفاده کرد؛ آن را در چت یا آرگومان فرمان نگذارید. بدون کلید در اجرای غیرتعاملی، برنامه پیش از هر درخواست شبکه متوقف می‌شود.

پس از مشاهدهٔ نتیجهٔ آزمون و بررسی صورتحساب، برای جلسهٔ تعاملی:

```sh
python3 scripts/claude_deepseek.py start
```

در داخل Claude، `/status` باید مدل DeepSeek و نشانی OpenRouter را نشان بدهد. گزارش مصرف حساب نیز باید همین مسیر را تأیید کند. نباید برای این آزمایش از حساب اصلی Claude خارج شد. برای برگشت کافی است این جلسه را ببندید؛ فرمان معمول `claude` از تنظیم معمول خود استفاده می‌کند.

## چه چیزی هنوز چک نشده؟

| موضوع | وضعیت |
|---|---|
| اتصال واقعی و کیفیت DeepSeek در Claude | منتظر کلید؛ هیچ پاسخ مدل دریافت نشده |
| دسترسی و پرداخت از ایران | نیازمند شاهد واقعی حساب و اتصال؛ این بسته تأییدش نمی‌کند |
| میزبان دقیق در OpenRouter | هنوز انتخاب/ثابت نشده؛ پیش از مقایسهٔ کیفیت باید مسیر ثبت و ثابت شود |
| حافظه، hookها، MCP، افزونه‌ها و تنظیم‌های شخصی | به این جلسهٔ آزمایشی وارد نشده‌اند؛ انتقال هرکدام بعد از قبولی اتصال انجام می‌شود |
| ساب‌ایجنت | در این آزمایش ممنوع است؛ راه‌اندازی و مدل آن نیازمند هماهنگی جدا با حبیب است |
| افزونهٔ VS Code | مسیر جدا نیز آماده شده؛ رابط زنده و اتصال مدل هنوز آزموده نشده است |
| سقف هزینه | قبل از اجرا از سرویس کنترل می‌شود؛ تخمین `--max-budget-usd` در Claude به‌تنهایی ضامن صورتحساب مدل خارجی نیست |

نکتهٔ مستند: OpenRouter سازگاری کامل Claude Code را فقط برای ارائه‌دهندهٔ اصلی Anthropic تضمین می‌کند؛ بنابراین DeepSeek در این مسیر باید آزموده شود و آماده‌کردن تنظیم، اثبات سازگاری کامل نیست. [راهنمای اتصال](https://openrouter.ai/docs/guides/coding-agents/claude-code-integration)

منابع: [متادیتای سقف کلید](https://openrouter.ai/docs/api/api-reference/api-keys/get-current-api-key)، [جداسازی پوشهٔ تنظیم Claude](https://code.claude.com/docs/en/settings). گزینه‌های اجرایی با `claude --help` نسخهٔ نصب‌شده تطبیق داده شده‌اند.

شرط رد آماده‌سازی: «اگر بدون کلید رفت سراغ شبکه، کلید نامحدود را قبول کرد یا مسیر مدل دیگری را گرفت، قبول نیست.» آزمون‌های آفلاین عمداً نشانی API، مدل فرزند و سقف هزینه را خراب می‌کنند و باید رد شوند. این شرط مربوط به راه‌انداز است؛ معیار کامل مهاجرت همان معیار تأییدشدهٔ حبیب در برنامهٔ مادر است.

## افزونهٔ VS Code — آماده‌سازی جدا

با تأیید حبیب در ۱۹:۲۲، افزونه هم به دامنهٔ آماده‌سازی اضافه شد. تنظیم‌های ماشین‌محور افزونه را داخل تنظیم همان پوشه گذاشتن کافی نیست؛ برای همین یک پوشهٔ دادهٔ جدا برای VS Code ساخته شده است. افزونهٔ نصب‌شدهٔ `2.1.323` دوباره استفاده می‌شود و نصب/به‌روزرسانی انجام نشده است.

| فایل | کار |
|---|---|
| `.runtime/vscode-deepseek/User/settings.json` | تنظیم پنجرهٔ جدا؛ دارای مسیر راه‌انداز، بدون کلید |
| `scripts/vscode_deepseek_wrapper.py` | واسطهٔ اجرای باینری افزونه؛ مدل، مسیر و سقف کلید را پیش از اجرای آزمایشی کنترل می‌کند |
| `claude-api/deepseek.code-workspace` | فضای کاری نمونه؛ بازکردن مستقیم این فایل به‌تنهایی کافی نیست |
| `.runtime/claude-deepseek` | محل سابقهٔ همین آزمایش، جدا از چت‌های عادی |

بررسی محلی، بدون کلید:

```sh
python3 scripts/vscode_deepseek.py check
python3 scripts/test_vscode_deepseek.py
```

بعداً، وقتی کلید آماده بود، از ترمینال ریشهٔ پروژه این فرمان پنجرهٔ جدا را باز می‌کند:

```sh
python3 scripts/vscode_deepseek.py open
```

کلید به شکل پنهان پرسیده می‌شود؛ قبل از بازکردن پنجره سقف آن بررسی می‌شود. اگر VS Code آزمایشی از قبل باز است، ابتدا همان پنجره را ببندید تا کلید تازه به فرایند تازه برسد. پنجرهٔ عادی و چت‌های قبلی را نبندید. در پنجرهٔ تازه، افزونهٔ Claude Code را باز کنید و فایل `sample.txt` را برای خواندن بدهید. تاریخچه، افزونه‌های Claude، حافظه و ابزارهای شخصی هنوز به این آزمایش منتقل نشده‌اند.

فرمان `--version` واقعاً از واسطه به باینری نصب‌شده فرستاده و پاسخ نسخه دریافت شد. این فقط قرارداد اجرای فرایند را می‌سنجد؛ اثبات کارکرد پنل، گفتگو، مجوزها یا مدل نیست. بدون کلید، درخواست عادی از واسطه رد می‌شود. برای برگشت، پنجرهٔ آزمایشی را ببندید؛ تنظیم VS Code اصلی تغییر نکرده است.

## تغییر روش با تأیید حبیب — ۲۰۲۶-۱۱-۱۳

راه‌انداز افزونه اکنون CLAUDE_CONFIG_DIR را روی /Users/habib/.claude می‌گذارد؛ تاریخچه و تنظیمات اصلی استفاده می‌شود. محدودیت‌های آزمایشی setting-sources، MCP خالی و ممنوعیت Agent/Task دیگر در wrapper تزریق نمی‌شوند. آرگومان‌های افزونه حفظ و فقط مدل و مسیر اتصال عوض می‌شوند. تنظیمات عمومی و کد افزونه ویرایش نشده‌اند. تنظیمات پنجرهٔ آزمایشی قبل از تغییر در settings.before-shared-history.json پشتیبان دارد. شش آزمون بدون اتصال گذشت؛ خرابکاری مسیر تاریخچه در کپی موقت آزمون را شکست. بازخوانی پنجره و نمایش تاریخچه هنوز تأیید نشده. ادامهٔ چت و ارسال سابقه به مدل در این مرحله اجرا نشده است. شرط اجباری سقف کلید با دستور حبیب حذف شده؛ توضیحات قدیمی سقف الزام جاری نیستند.

## محیط پیش‌فرض VS Code — ۱۳ نوامبر ۲۰۲۶
طبق درخواست حبیب، تنظیم اتصال به پروفایل معمولی VS Code منتقل شد.
- `~/Library/Application Support/Code/User/settings.json` اکنون از `scripts/vscode_default_deepseek.py` استفاده می‌کند.
- این راه‌انداز کلید را از Keychain با service `habib-claude-code-openrouter` و account `default-vscode` می‌خواند؛ کلید در تنظیمات نوشته نشده است.
- راه‌انداز قبلی `~/.claude/claude_abzar_kam.sh` در زنجیره حفظ شده تا سیاست ابزارهای قبلی عوض نشود.
- تاریخچه همان `~/.claude` است؛ مدل و fallback روی DeepSeek نگه داشته می‌شوند. شکست دریافت کلید باعث توقف می‌شود، نه برگشت به حساب Claude.
- `vscode_deepseek.py open` دیگر `--user-data-dir` و workspace آزمایشی نمی‌دهد و پوشهٔ جاری را در VS Code معمولی باز می‌کند.
- نسخهٔ قبل از تغییر تنظیمات: `.runtime/default-profile-backup/settings.before-default-deepseek.json`.
- ۱۲ آزمون راه‌انداز گذشت و نسخهٔ باینری از زنجیرهٔ واقعی خوانده شد. پاسخ زندهٔ مدل در پنجرهٔ معمولی هنوز آزمایش نشده است.
- پنجره‌های قدیمیِ محیط جدا تا بسته‌شدن فرایند آن، همچنان وجود دارند؛ پوشه‌های آزمایش و سابقه حذف نشده‌اند.
