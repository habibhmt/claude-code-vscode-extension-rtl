# تجربهٔ کاربران: مدل یکسان، نتیجهٔ متفاوت در محیط‌های مختلف

بررسی در ۲۰۲۶-۱۱-۱۳. این‌ها گزارش دست‌اولِ دیگران‌اند؛ روی سیستم حبیب بازتولید نشده‌اند. نمونه‌ها برای کشف خطر و طراحی آزمون انتخاب شده‌اند، نه برآورد آماریِ رضایت کاربران. نسخه‌های قدیمی را عیب قطعی نسخهٔ امروز حساب نمی‌کنیم.

| محیط | تجربهٔ مثبت یا منفی | جزئیات و اعتبار | نتیجه برای برنامه |
|---|---|---|---|
| Claude Code + Flash 4.1 | کاربر ساخت جست‌وجوی YouTube و استفاده از Chrome DevTools MCP را مفید توصیف می‌کند، اما بازبینی چندبارهٔ کد لازم داشته | [نوشتهٔ اصلی](https://www.reddit.com/r/DeepSeek/comments/1wm40ml/claudecodex_user_trying_41_flash_thoughts/)؛ صفحه حدود یک ماهه، نسخهٔ دقیق هارنس نامعلوم؛ هزینه‌ها ادعای کاربر است | نامزد مناسب برای شروع، ولی ارزانی با نیاز به دخالت و اصلاح سنجیده شود. |
| Claude Code + DeepSeek از DashScope | خلاصه‌سازی زودهنگام به علت شمارش نادرست توکن گزارش شده | [گزارش ۱۰۳۹۰۱](https://github.com/anthropics/claude-code/issues/103901)، ۲۱ اکتبر ۲۰۲۶، 2.1.304/305؛ نمونهٔ جریان پاسخ و روش تکرار دارد | آزمون متن بلند و هزینه لازم است؛ این خطا را به همهٔ مسیرهای DeepSeek تعمیم ندهیم. |
| Claude Code، بازگشایی سابقه | چت جدید کار می‌کرد ولی بازکردن چت در افزونه شکست می‌خورد؛ CLI می‌توانست ادامه دهد | [گزارش ۸۵۹۷۷](https://github.com/anthropics/claude-code/issues/85977)، ۱۲ اوت، افزونهٔ 2.1.227 روی Windows؛ بسته‌شدن به علت بی‌فعالیتی اثبات اصلاح نیست | بازگشایی در همان رابط روزمرهٔ حبیب باید آزموده شود. |
| Codex Desktop + DeepSeek | چت معمولی موفق، ولی ویرایش متن انتخاب‌شده در پیش‌نمایش ناموفق؛ مسیر جانبی به حساب/مدل OpenAI تکیه داشت | [گزارش ۳۷۳۱۵](https://github.com/openai/codex/issues/37315)، ۶ اوت، نسخهٔ 26.730.61639 روی مک؛ لاگ و مسیر درخواست دارد | انتقال مدل اصلی کافی نیست؛ دکمه‌ها و کارهای جانبی جدا آزموده شوند. رفع در نسخهٔ فعلی نامعلوم است. |
| Codex + DeepSeek، ساب‌ایجنت | فرزند ساخته می‌شد ولی متن وظیفه منتقل نمی‌شد | [گزارش ۳۹۲](https://github.com/deepseek-ai/awesome-deepseek-agent/issues/392)، ۱۹ اوت، Codex 0.148؛ قدیمی‌تر از نسخهٔ محلی 0.166 | آزمون واگذاری و تحویل نتیجه لازم است؛ این گزارش اثبات خرابی نسخهٔ فعلی نیست. |
| DSH + API مستقیم | چند کاربر آن را برای Flash 1017 ترجیح داده‌اند؛ نویسندهٔ بحث همین مسیر را انتخاب کرده است | [بحث اصلی](https://www.reddit.com/r/DeepSeek/comments/1xbw5pe/what_is_the_best_harness_and_endpoint_provider/)؛ حدود سه هفته اخیر؛ نسخه و مسئلهٔ ثابت ندارند | دلیل کافی برای حضور DSH در آزمون هست؛ دلیل کافی برای اعلام بهترین‌بودن نیست. |
| DSH، اجرای طولانی SDK | هنگام تغییر پلاگین، بعضی ابزارها از درخواست جا می‌افتادند؛ شکست بارگذاری می‌توانست تنظیم خالی بنویسد | [گزارش ۳۵۰۹](https://github.com/deepseek-ai/deepseek-harness/discussions/3509)، ۲۰ اوت؛ توسعه‌دهنده شاخهٔ اصلاح و تست ارائه کرده | راه‌اندازی، تغییر ابزار و بازیابی از خطا باید روی کپی سنجیده شود؛ وضعیت اصلاح امروز بررسی نشده. |
| Open WebUI + OpenRouter + DeepSeek | پیوست دانش/مهارت در حالت فکرکردن خطای ۴۰۰ می‌داد؛ اتصال مستقیم در گزارش کار می‌کرد | [گزارش ۳۴۱۷۷](https://github.com/open-webui/open-webui/issues/34177)، ۱۱ نوامبر، نسخهٔ 0.13.3؛ تنظیم Provider=llama.cpp و میزبان DeepSeek ثابت | ناسازگاری قالب پیام را با ضعف مدل اشتباه نکنیم؛ این گزارش دربارهٔ Open WebUI است، نه حکم کلی Claude/Codex. |

| پرسش حبیب | جمع‌بندی مشروط |
|---|---|
| کدام هارنس با DeepSeek بهتر مچ می‌شود؟ | شواهد موجود برندهٔ عمومی تعیین نمی‌کنند. برای سیستم فعلی تو Claude Code و Codex کمترین تغییر را دارند؛ DSH مدعی جدیِ آزمایش مستقل است. |
| پس چرا مستقیم نرویم روی DSH؟ | انتقال حافظه، نگهبان‌ها، سؤال و صف پیام هنوز اثبات نشده؛ خود محصول هم پیش‌نمایش است. سرعت یک تجربهٔ کاربری این فاصله را پر نمی‌کند. |
| OpenRouter کیفیت را کم می‌کند؟ | حکم عمومی نداریم. مدل، میزبان، قالب پیام، فشردگی و تنظیمات می‌توانند فرق کنند؛ دو مسیر باید با همان کار مقایسه شوند. |
| از ایران راحت کار می‌کند؟ | تجربهٔ مستقل با مشخصات کاملِ محل استفاده، پرداخت، مدل/میزبان و دورهٔ پایداری تأیید نشد؛ تبلیغ فروشنده به‌جای آن استفاده نشده است. |

## آزمایش مقایسه‌ای پیشنهادی

| دور | چیز ثابت | چیز متغیر | خروجی |
|---|---|---|---|
| مدل | هارنس، میزبان تا حد امکان، کار و اجازه‌ها | Flash 1017، Qwen3.8-27B، Kimi K3.1 Pro | قبولی کار، دخالت حبیب، زمان و هزینه |
| هارنس | Flash 1017، میزبان و ورودی | Claude Code، Codex، DSH | کیفیت ابزارخوانی و ادامهٔ کار |
| ارائه‌دهنده | مدل دقیق، هارنس و ورودی | مستقیم، OpenRouter با میزبان ثابت، AvalAI | خطا، سرعت، قیمت صورتحساب و سازگاری |

Qwen3.8-27B مجوز Apache-2.0 دارد؛ Kimi K3.1 Pro مجوز اختصاصی دارد. هر دو فایل مدل منتشرشده دارند، ولی این برنامه از API استفاده می‌کند. [کارت Qwen](https://huggingface.co/Qwen/Qwen3.8-27B)، [کارت Kimi](https://huggingface.co/moonshotai/Kimi-K3.1-Pro)، [API Qwen](https://openrouter.ai/qwen/qwen3.8-27b)، [API Kimi](https://openrouter.ai/moonshotai/kimi-k3.1-pro). برتری آن‌ها روی کار حبیب هنوز سنجیده نشده است.

هر اجرا باید نسخهٔ دقیق، زمان، مسیر API، پاسخ ابزارها، هزینهٔ واقعی و نتیجهٔ داوری را ثبت کند. ابتدا جابه‌جایی خودکار میزبان خاموش باشد؛ بعد فقط مقصدهای قبول‌شده پشتیبان شوند. [تنظیم میزبان در OpenRouter](https://openrouter.ai/docs/guides/routing/provider-selection)
